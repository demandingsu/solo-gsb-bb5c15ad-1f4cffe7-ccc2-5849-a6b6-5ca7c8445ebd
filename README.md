# SRT 字幕时轴修复工具

一个基于 **Node.js + Express + 原生 HTML/CSS/JavaScript** 的 Web 应用，用于修复 SRT 字幕的显示时间，保护用户指定的场景切点不被字幕跨越，并支持把关键字幕锁定为不可移动的时间锚点。

## 功能

- 上传 UTF-8 编码的 `.srt` 字幕文件。
- 输入一条或多条不可跨越的场景切点：
  - 支持秒：`12.5`
  - 支持 `分:秒`：`01:30.500`
  - 支持完整 SRT 时间：`00:01:30,500`
  - 可换行，也可用逗号、分号分隔。
- 输入要锁定的字幕编号（可选）：
  - 编号按字幕在文件中的顺序从 1 开始（即结果表中的 `#` 列）；
  - 可用逗号、空格或换行分隔，例如 `3, 7, 12`；
  - 锁定字幕严格保留原始起止时间，不参与最短时长/CPS 延长，也不会被移动；
  - 锁定字幕作为**双向时间锚点**参与约束传播：前序字幕必须在锚点开始前让位，后续字幕必须在锚点结束后排布。
- 同时联动满足：
  - 每条未锁定字幕的最短显示时长；
  - 最大每秒字符数（CPS）；
  - 相邻字幕之间的最小间隔；
  - 原有字幕顺序；
  - 字幕不得开始于切点之前且结束于切点之后。
- 有解时在全部可行解中最小化整体时移（最小二乘意义），提供修复前后对照表（锁定行有标记），并下载与预览一致的修复后 SRT。
- 无解时在页面中红色高亮造成冲突的**最短连续字幕段**（包含相关锚点），并给出：
  - 最少需要的时间；
  - 可用时间；
  - 超出时间；
  - 冲突涉及的锁定字幕编号；
  - 是单条时长不足、连续字幕容量不足、切点两侧顺序冲突，还是锁定字幕覆盖切点。

## 使用 Docker Compose 启动

要求本机已安装 Docker 与 Docker Compose。

```bash
docker compose up --build
```

该命令会自动：

1. 构建 Node.js 镜像；
2. 执行 `npm ci --omit=dev` 安装生产依赖；
3. 启动 Express 服务。

启动后在浏览器打开：

<http://localhost:3000>

后台运行：

```bash
docker compose up --build -d
```

停止：

```bash
docker compose down
```

## 配置

通常不需要额外配置。`compose.yaml` 暴露容器 `3000` 端口到宿主机 `3000`：

```yaml
ports:
  - "3000:3000"
environment:
  NODE_ENV: production
  PORT: 3000
```

如果宿主机的 3000 端口被占用，可把左侧端口改为其他端口，例如：

```yaml
ports:
  - "8080:3000"
```

然后访问 <http://localhost:8080>。容器内仍监听 `PORT=3000`。

## 页面参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 最短显示时长 | `0.5` 秒 | 每条未锁定字幕至少显示的时间 |
| 最大 CPS | `15` 字符/秒 | 字幕时长至少为 `字符数 / CPS`，向上取整到毫秒 |
| 最小间隔 | `80` 毫秒 | 上一条结束到下一条开始之间至少保留的时间 |
| 场景切点 | 空 | 字幕时间不得覆盖的切点列表 |
| 锁定字幕编号 | 空 | 保留原始起止时间的字幕编号（从 1 开始），可用逗号、空格或换行分隔 |

字符数统计会忽略：

- 字幕标签，例如 `<b>...</b>`、`<font ...>...</font>`；
- ASS 风格覆盖，例如 `{\an8}`；
- 空白字符。

中日韩文字和拉丁字符均按一个可见字符计算。

## 调整算法说明

每条未锁定字幕 i 的最低时长为：

```text
required_i = max(原始时长, 最短显示时长, ceil(字符数 × 1000 / 最大CPS))
```

锁定字幕的占用区间固定为原始时长（不延长、不移动）。

设相邻字幕最小间隔为 `gap`，则调整后的开始时间必须满足：

```text
start_i + required_i + gap <= start_(i+1)
```

对于切点 `cut`，字幕不能满足 `start < cut < end`。系统先按每条字幕的原始中点决定它属于切点左侧还是右侧；该归属允许调整相邻边界，但不允许字幕越过切点。

求解时把开始时间转换为累计偏移后的单调序列，在每个切点区间的上下界内做有界单调回归，使开始时间整体尽量少偏离原始时轴。

### 锁定字幕（双向时间锚点）

锁定编号后，该字幕的开始时间在求解器中被钉死为原始值（下界 = 上界 = 原始开始时间），等效于单调链上的点约束，随有界单调回归向两侧传播——不是先求解再覆盖时间：

- 前序字幕必须在 `锚点开始 − 最小间隔` 之前结束，可能被整体提前；
- 后续字幕必须在 `锚点结束 + 最小间隔` 之后开始，可能被整体推后；
- 目标函数不变：在全部可行解中最小化整体时移（最小二乘意义）。

### 无解诊断

无解的必要条件可表示为某一段连续字幕的最低时间需求超过其允许范围（允许范围的端点可以是时间轴起点、切点或锁定锚点）。系统扫描最短窗口并返回包含相关锚点的最小冲突段：

- 单条字幕无法放入所在切点区间时，只标这一条；
- 多条字幕连续联动后容量不足时，返回最短连续段，并列出段内冲突的锁定字幕；
- 原始中点归属导致顺序反转时，标出相邻的两条；
- 锁定字幕的原始区间覆盖切点时，单独标出该锁定字幕，说明锁定时长与切点内侧可容纳的跨度。

## HTTP 接口

### `POST /api/fix`

`multipart/form-data`：

- `subtitle`：SRT 文件；
- `minDurationSeconds`：最短显示时长（秒）；
- `maxCps`：最大每秒字符数；
- `minGapMs`：最小间隔（毫秒）；
- `cuts`：切点文本；
- `locks`：锁定字幕编号文本（可选，从 1 开始，逗号/空格/换行分隔）。

返回：

- `200`：有解，包含原始字幕、修复后字幕（每条带 `locked` 标记）、顶层 `lockedIndices`、序列化后的 SRT 与统计信息（含 `locked` 数量）；
- `422`：字幕可解析但约束无解，包含最短冲突段及原因；`conflict.lockedIndices` 列出冲突涉及的锁定字幕；
- `400`：文件缺失、SRT 格式错误、参数无效或锁定编号不存在。

健康检查：

```bash
curl http://localhost:3000/api/health
```

带锁定字幕的调用示例：

```bash
curl -F "subtitle=@movie.srt" \
     -F "cuts=12.5, 01:30.500" \
     -F "locks=3, 7, 12" \
     http://localhost:3000/api/fix
```
